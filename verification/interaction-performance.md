# 本轮交互与性能验证（2026-09-09）

用户确认保留当前翻页交互，不再追求翻页与官网完全相同。本轮保留现有双页、单页、书角翻页及侧栏逻辑。

## 已实现

- 修改模板使用可视化画布，支持拖动图框、八方向拉伸、圆形/矩形、增删图框，保存为独立自定义模板。
- 模板装饰和文字随自定义模板保存，画册编辑时图框依然固定，照片只改变内部裁切。
- 预览栏两端固定首尾按钮，定位第一张内页或最后一张内页，直接定位而非逐页播放。
- 未选素材采用虚拟列表；只挂载可见区域及缓冲区域。已选最多九张仍支持拖动排序。
- 页面缩略图进入视口附近才生成，同时最多生成两张；小预览使用 240px 素材缩略图。
- 图片解码最多三个并发；解码图片缓存按估算像素内存限制为 48 MiB，原图导出不常驻缓存。该上限是缓存上限，不是整个浏览器内存上限。
- 修复照片快速拖动的最终位置提交与拖动后误触素材库；修复翻页组件收到空子项时的异常。

## 验证证据

- `npm run typecheck`、`npm run lint`、`npm test`、`npm run build` 均通过；17 项测试。
- 浏览器：双页和单页均能跳至第 5 页并回到第 1 页，端点按钮正确禁用。
- 浏览器：拖动首图框并拉伸右下角，保存再打开，位置 18.2143% / 22.5811%、尺寸 34.5222% / 24.9428% 均恢复。
- `verification/performance.html` 使用 5000 条合成素材记录。初始 DOM 图片 18 张；滚动 10000px 后图片 27 张，对应照片 265–291。
- 以上大列表检查验证虚拟化，而非 5000 张独立大原图的上传、解码或整体帧率基准。测试入口仅用于本地 Vite，未加入生产构建入口。

## 仍需后续验证

- 不同设备上的大批量独立原图导入与长画册整体内存、帧率。
- 原始完整复现目标中的其他界面、视频对照和导出验收仍需单独逐项完成；本轮不代表该完整目标已经实现。
